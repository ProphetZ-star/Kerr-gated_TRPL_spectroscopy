# 启动后 127.0.0.1 拒绝连接

修复日期：2026-10-31。

实际复现时，Windows 虚拟环境启动器 PID 为 28292，HTTP 服务 PID 为 31340。服务本身能够启动且 worker_alive 为 true，但 LocalService 把 PID 不同误判为另一个启动实例，主动关闭自己的后端，然后返回成功，页面因此收到连接拒绝。

现在每次启动生成独立 launch_id，通过内部命令行传给后端，并由 identity 接口返回。启动器使用该标识确认进程归属；PID 仅保留为诊断信息。launch_id 不是认证凭据，不替代会话 token。并发启动时仍只清理自己的子进程。

仅运行本问题相关回归：`tests/test_launcher_connection.py` 的 4 项，以及原报告 E3、E4（身份探测）、E19 共 3 项，合计 **7 项通过**。真实启动覆盖 python.exe 和 pythonw.exe，验证首页 HTTP 200、worker 健康、后端持续存活、重复启动复用同一服务及正常停止。没有打开浏览器或桌面窗口，没有运行完整验收，也未修改实验数据。

回归结果：`test-output/launcher-connection.xml`。
